# Markdown in Next.js

The renderer is a server component. It reads files, runs during a static build,
and ships no JavaScript to the browser for the Markdown itself.

## A server component in the App Router

There is no `use client` in this file or in the renderer entry, so React keeps
it on the server.

```tsx
// app/posts/[slug]/page.tsx
import { readdir, readFile } from 'node:fs/promises'
import Markdown, { defineMarkdownPreset, gfm } from '@react-markdown-kit/renderer'

// The dialect, decided once for the whole app.
const preset = defineMarkdownPreset({ extensions: [gfm()] })

export async function generateStaticParams() {
  const files = await readdir('content')
  return files
    .filter((file) => file.endsWith('.md'))
    .map((file) => ({ slug: file.replace(/\.md$/, '') }))
}

export default async function Page({ params }: { params: Promise<{ slug: string }> }) {
  const { slug } = await params
  const content = await readFile(`content/${slug}.md`, 'utf8')

  return (
    <article className="rmk-document">
      <Markdown preset={preset}>{content}</Markdown>
    </article>
  )
}
```

Three things make that work.

- **No `use client`.** React treats the directive as a module boundary, so a
  module without one stays on the server side of the graph.
- **No browser global.** Reading from `node:fs` in the same component is safe,
  and the same code runs in a static export with no DOM.
- **Synchronous rendering.** No `dynamic()`, no `ssr: false`, no `useEffect`.
  There is also no `MarkdownAsync` and no `MarkdownHooks`, so an async remark
  or rehype plugin will not run
  (<Link to="/docs/compatibility">compatibility</Link>).

The `rmk-document` class is optional. It scopes the shipped stylesheet, which
you import once in the root layout if you want the typography:
<Link to="/docs/styling">styling</Link>.

## Precompile what does not change

Parsing is about two thirds of the work. Hoist it out of the request path and
re-render from the compiled document, which is about 2.8 times faster in the
benchmark (<Link href={blob('benchmarks/README.md')}>results</Link>,
<Link href={blob('benchmarks/run.mjs')}>`benchmarks/run.mjs`</Link>).

```tsx
import { readFile } from 'node:fs/promises'
import Markdown, { compileMarkdown } from '@react-markdown-kit/renderer'

// Parsed once per process, not once per request.
const TERMS = compileMarkdown(await readFile('content/terms.md', 'utf8'))

export default function Page() {
  return <Markdown document={TERMS} />
}
```

A compiled document is plain JSON. It survives a cache, a queue and an HTTP
boundary, so it can also come from a build step, from `unstable_cache`, or from
a CMS webhook that compiles on publish. The content policy runs again on the
way to HTML, so compiling early is not a way around it
(<Link href={blob('packages/renderer/tests/render.dom.test.tsx#L107')}>test</Link>).

<Link to="/docs/renderer/compiling">Compiling documents</Link>

## Route handlers and metadata

The same import works outside a page. A route handler can compile Markdown and
return the document as JSON, and `generateMetadata` can read the front matter
your own loader parsed, since the renderer takes the body as a string.

```tsx
// app/api/doc/[slug]/route.ts
import { NextResponse } from 'next/server'
import { compileMarkdown } from '@react-markdown-kit/renderer'

export async function GET(_request: Request, { params }: { params: Promise<{ slug: string }> }) {
  const { slug } = await params
  return NextResponse.json(compileMarkdown(await load(slug)))
}
```

## Markdown from users

Raw HTML is rendered as visible escaped text rather than executed, and URL
schemes outside `http`, `https`, `irc`, `ircs`, `mailto` and `xmpp` are
emptied. Both defaults are asserted in
<Link href={blob('packages/renderer/tests/render.dom.test.tsx#L56')}>`packages/renderer/tests/render.dom.test.tsx`</Link>,
and they apply to a server component exactly as they do in the browser.
<Link to="/docs/security">The security model</Link>.

## Streaming a model's answer

A Next.js chat route streams tokens to a client component. Hand the renderer
the longer string on every token; every prefix renders, and the finished blocks
stay byte-identical while the next one is written
(<Link href={blob('packages/renderer/tests/streaming.test.tsx')}>streaming tests</Link>).

## The editor is the other case

The editor is interactive, so it is a client component. That is precisely why
it is a separate package: installing the renderer never drags editor code into
a server bundle, and a packaging test asserts it against the renderer's own
modules
(<Link href={blob('tests/packaging.test.ts#L205')}>`tests/packaging.test.ts`</Link>).
<Link href={blob('scripts/pack-check.mjs')}>`scripts/pack-check.mjs`</Link> packs
the real npm tarballs and installs them into clean consumer fixtures in CI.

```tsx
'use client'

import { MarkdownEditor } from '@react-markdown-kit/editor'
```
