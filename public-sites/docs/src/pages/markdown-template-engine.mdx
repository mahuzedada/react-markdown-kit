# Markdown template engine

Fill a Markdown document in with typed application data. Placeholders get resolved
inside the parser, so a value can't turn into Markdown structure.

```bash
npm install @react-markdown-kit/renderer @react-markdown-kit/template
```

```tsx
import Markdown from '@react-markdown-kit/renderer'
import { template } from '@react-markdown-kit/template'

<Markdown extensions={[template({ data: { user: { name: 'Chatis' } } })]}>
  {'# Hello {{user.name}}'}
</Markdown>
```

`template()` is a plugin. There's no separate engine to call; the renderer parses with
your preset and the plugin fills in the tree. `compileMarkdown` runs the same extension
outside React, in a service, a worker, a CLI, an email job or a PDF pipeline.

<TemplateExample
  title="Same source, different data"
  gfm
  markdown={`## Account review for {{customer.name}}\n\nRenews {{renewsAt | date:"long"}}.\n\n| Item | Amount |\n| --- | ---: |\n| Plan | {{amounts.plan \\| currency:"USD"}} |`}
  datasets={[
    { label: 'Acme', data: { customer: { name: 'Acme Industrial' }, renewsAt: '2026-11-01', amounts: { plan: 4800 } } },
    { label: 'Cedarline', data: { customer: { name: 'Cedarline Mutual' }, renewsAt: '2027-02-15', amounts: { plan: 19200 } } },
    { label: 'Acme in French', locale: 'fr-FR', data: { customer: { name: 'Acme Industrial' }, renewsAt: '2026-11-01', amounts: { plan: 4800 } } },
  ]}
/>

Both panes above are live. The left one is the authored source, and it's the same string
for every dataset. The right one is an actual `<Markdown>` rendering the document that
`compileMarkdown` produced. A formatter inside a table cell keeps its escaped pipe (that's
covered by
<Link href={blob('tests/template-table-formatters.test.ts#L25')}>`template-table-formatters.test.ts`</Link>).

## Typed, then validated

TypeScript generics catch mistakes at compile time:

```ts
template<ReportData>({ data })
```

Runtime schemas catch them at the boundary. They go through
[Standard Schema](https://standardschema.dev), so Zod, Valibot and ArkType all work
without an adapter, and the package doesn't depend on any of them.

```ts
template({ data, schema: ReportSchema })
```

The validator is detected by its `~standard` member, so you don't have to import or
register anything.
<Link href={blob('plugins/template/tests/schema.test.ts#L59')}>`schema.test.ts`</Link>
runs the same template against two Standard Schema vendors, one reporting issue paths as
arrays the way Zod does and one reporting them as objects and coercing the way Valibot
does. It checks that resolution reads the validator's output instead of the raw input,
that issue paths become diagnostic paths, and that an async validator gets a diagnostic
instead of being awaited.

A missing required value is an error diagnostic and renders nothing (or your `fallback`).
You won't end up with a document that looks ready to send but has a blank where a number
should be
(<Link href={blob('plugins/template/tests/resolve.test.ts#L53')}>missing-value tests</Link>).

## Formatting and localization

There are six built-in formatters: `number`, `currency`, `percent`, `date`, `time` and
`datetime`.

```text
{{revenue | currency:"USD"}}
{{renewsAt | date:"long"}}
{{share | percent:1}}
```

Two rules have their own tests, because getting either one wrong is expensive.

- **Currency always carries an explicit ISO 4217 code.** `{{revenue | currency}}` is an
  error, because it won't guess a currency from the locale. `currency:"USD"` in `fr-FR`
  renders `$US` and stays in dollars
  (<Link href={blob('plugins/template/tests/formatters.test.ts#L22')}>currency tests</Link>).
- **The time zone is explicit and defaults to `UTC`**, so a report doesn't change
  depending on which machine rendered it
  (<Link href={blob('plugins/template/tests/formatters.test.ts#L82')}>date and time tests</Link>).

`locale` and `timeZone` are options on `template()`. You still pick the authored source
per language. Switch to the third dataset above to see the same source rendered for
`fr-FR`.

## Data cannot inject structure

This matters most once authored documents start getting filled with runtime data.

Values are placed into the parsed syntax tree as nodes. They're never substituted into
the source text and re-parsed, so a customer named `**Administrator**` renders as those
literal characters.

<TemplateExample
  title="Hostile values stay literal"
  markdown={`## Hello {{name}}\n\nSigned, {{name}}.`}
  datasets={[
    { label: 'Ordinary', data: { name: 'Dana Okafor' } },
    { label: 'Bold attempt', data: { name: '**Administrator**' } },
    { label: 'Heading attempt', data: { name: '\n# Pwned\n' } },
    { label: 'Table attempt', data: { name: '\n| a | b |\n| --- | --- |\n| 1 | 2 |\n' } },
    { label: 'Script attempt', data: { name: '<script>alert(1)</script>' } },
  ]}
>
  None of these values can create a heading, a table row, a link destination, an HTML tag
  or a code fence.
</TemplateExample>

Three test files cover this, with 152 cases between them:

| What is asserted | Where |
| --- | --- |
| 22 hostile values in a heading and a paragraph keep the document's node types and their own characters, and survive a serialize and re-parse | <Link href={blob('plugins/template/tests/injection.test.ts#L21')}>`injection.test.ts`</Link> (77) |
| 12 line-start constructs, in 5 authored contexts, cannot become structure after `documentToMarkdown` and a GFM re-parse | <Link href={blob('tests/template-serialization-safety.test.ts#L16')}>`template-serialization-safety.test.ts`</Link> (62) |
| The same claim written again without the plugin's own helpers, plus prototype-chain paths | <Link href={blob('tests/template-security-independent.test.ts')}>`template-security-independent.test.ts`</Link> (13) |

Run them yourself:

```bash
pnpm test -- plugins/template/tests/injection.test.ts \
  tests/template-serialization-safety.test.ts \
  tests/template-security-independent.test.ts
```

A few more rules come out of the same design:

- **Code contexts are literal.** A `{{path}}` inside inline code, a fenced block or an
  indented block is treated as documentation about a template and left alone
  (<Link href={blob('plugins/template/tests/literal-contexts.test.ts#L15')}>literal-context tests</Link>).
  That's how this page can be written with the engine installed.
- **A URL binding is all or nothing.** A placeholder has to be the entire link
  destination, and the resolved value still goes through the protocol policy, so
  `javascript:` can't end up in an `href`
  (<Link href={blob('plugins/template/tests/links.test.ts#L72')}>partial-URL tests</Link> and
  <Link href={blob('plugins/template/tests/links.test.ts#L97')}>destination policy tests</Link>).
- **Prototype-chain paths never resolve.** `__proto__`, `constructor` and `prototype`
  are refused at resolve time, and nothing gets written to `Object.prototype`
  (<Link href={blob('plugins/template/tests/paths.test.ts#L41')}>path tests</Link>).

Diagnostics include the path but never the runtime value, so they're safe to log
(<Link href={blob('plugins/template/tests/links.test.ts#L115')}>test</Link>).

## It renders through the same renderer

Resolution happens inside the renderer's own compile step, so there's no stringify and
reparse in between. You can also cache a compiled document and hand it to `<Markdown
document>` later.

```ts
const document = compileMarkdown(source, { preset, extensions: [template({ data })] })
```

If you need Markdown text back (for an email body or a file on disk), serialize the
compiled document. Serializing re-escapes, so a value of `**Administrator**` comes back
out as `\*\*Administrator\*\*` and still reads as literal text
(<Link href={blob('plugins/template/tests/to-markdown.test.ts#L13')}>serializer tests</Link>).

```ts
import { compileMarkdown, documentToMarkdown } from '@react-markdown-kit/renderer'

const document = compileMarkdown(source, { extensions: [template({ data })] })
await writeFile('report.md', await documentToMarkdown(document))
```

## Authoring the template

`@react-markdown-kit/template/editor` turns each placeholder into a chip in the rich
editor, with a label and a sample-data preview, and adds an insert-variable command to
the toolbar. Preview data only changes what the author sees. It's never saved.

```tsx
import { templateVariables } from '@react-markdown-kit/template/editor'

<MarkdownEditor
  value={source}
  onChange={setSource}
  extensions={[templateVariables({ variables, previewData: sample })]}
/>
```
