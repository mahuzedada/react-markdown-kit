# React Markdown renderer

Turn a Markdown string into React elements with one component.

```bash
npm install @react-markdown-kit/renderer
```

```tsx
import Markdown from '@react-markdown-kit/renderer'

export function Post({ content }: { content: string }) {
  return <Markdown>{content}</Markdown>
}
```

That is the whole first-use experience. No provider, no stylesheet, no account,
no design system, no configuration.

## What you get by default

**CommonMark**, parsed with micromark rather than regular expressions. 554 of
the 652 official examples match exactly, and 96% do once the raw-HTML examples
the security policy intentionally drops are counted separately
(<Link href={blob('tests/commonmark.test.ts')}>`tests/commonmark.test.ts`</Link>).

**Safe rendering.** Raw HTML is not executed and unsafe URL schemes are
blocked, using the same algorithm `react-markdown` uses
(<Link href={blob('packages/renderer/tests/render.dom.test.tsx#L56')}>security tests</Link>).

**Plain semantic HTML.** No classes, no inline styles, nothing to override
(<Link href={blob('packages/renderer/tests/render.dom.test.tsx#L122')}>"emits no kit classes by default"</Link>).

**Server rendering.** No `use client` directive, so it works in server
components, during SSR and in static builds.

## Custom components

Map any element to your own component. Each override receives the usual props
and the source node.

```tsx
<Markdown components={{ a: AppLink, img: AppImage, code: CodeBlock }}>
  {content}
</Markdown>
```

Define that object at module scope. A new object on every render remounts every
overridden element. <Link to="/docs/renderer/components">Components
reference</Link>.

## GitHub Flavored Markdown

Tables, task lists, strikethrough, autolinks and footnotes, through a native
extension or the familiar plugin. Both are fixture-tested to produce the same
output (<Link href={blob('tests/gfm.test.ts')}>`tests/gfm.test.ts`</Link>).

```tsx
import Markdown, { defineMarkdownPreset, gfm } from '@react-markdown-kit/renderer'

const preset = defineMarkdownPreset({ extensions: [gfm()] })

<Markdown preset={preset}>{content}</Markdown>
```

## Presets

A preset is the dialect, decided once and shared. It holds the extensions, the
plugins and the options, so every call site renders the same Markdown the same
way, and `compileMarkdown` and the editor can be handed the same object.

```tsx
import { defineMarkdownPreset, gfm } from '@react-markdown-kit/renderer'

// One module, imported everywhere that renders content.
export const contentPreset = defineMarkdownPreset({
  extensions: [gfm()],
  remarkPlugins: [remarkDirective],
})
```

Build it at module scope. A preset built inside a component is a new dialect on
every render. <Link to="/docs/renderer/presets">Presets reference</Link>.

## Security defaults

Two defaults carry the weight, and both are asserted in
<Link href={blob('packages/renderer/tests/render.dom.test.tsx#L56')}>`packages/renderer/tests/render.dom.test.tsx`</Link>.

| Default | Behaviour | Test |
| --- | --- | --- |
| Raw HTML | Rendered as visible escaped text, never executed | <Link href={blob('packages/renderer/tests/render.dom.test.tsx#L57')}>"does not execute raw HTML by default"</Link> |
| `<script>` | Escaped, never emitted as an element | <Link href={blob('packages/renderer/tests/render.dom.test.tsx#L71')}>"escapes a script tag rather than emitting one"</Link> |
| `skipHtml` | Removes raw HTML instead of showing it; neither option executes it | <Link href={blob('packages/renderer/tests/render.dom.test.tsx#L77')}>"removes raw HTML entirely when skipHtml is set"</Link> |
| URL schemes | `http`, `https`, `irc`, `ircs`, `mailto`, `xmpp` pass; everything else is emptied | <Link href={blob('packages/renderer/tests/render.dom.test.tsx#L82')}>"blocks javascript: urls"</Link>, <Link href={blob('packages/renderer/tests/render.dom.test.tsx#L87')}>obfuscated protocols</Link> |
| Relative URLs | Untouched, because a colon after the first `/`, `?` or `#` is part of a path | <Link href={blob('packages/renderer/tests/render.dom.test.tsx#L103')}>"keeps relative and anchor urls"</Link> |
| Precompiled documents | The same policy runs, so compiling is not a bypass | <Link href={blob('packages/renderer/tests/render.dom.test.tsx#L107')}>"applies policy to a precompiled document too"</Link> |

## Server rendering

The entry has no `use client` directive and touches no browser global, so the
same component renders in a React server component, during SSR and in a static
build, with no JavaScript shipped for the Markdown itself.

```tsx
// app/posts/[slug]/page.tsx
import { readFile } from 'node:fs/promises'
import Markdown from '@react-markdown-kit/renderer'

export default async function Page({ params }) {
  const content = await readFile(`content/${params.slug}.md`, 'utf8')
  return <Markdown>{content}</Markdown>
}
```

Parsing is about two thirds of the work, so a document that does not change should
be parsed once. `compileMarkdown` returns plain JSON that survives a cache, a
queue or an HTTP boundary, and re-rendering from it is about 2.8 times faster
in the benchmark (<Link href={blob('benchmarks/README.md')}>results</Link>).

## Streaming input

Hand the component a longer string on every token and every prefix renders:
unclosed fences, half-written emphasis, a table mid-row. The finished blocks
above stay byte-identical while the next one is written
(<Link href={blob('packages/renderer/tests/streaming.test.tsx')}>streaming tests</Link>).
Two constructs legitimately rewrite themselves, and both are named on the
page below.

## Coming from react-markdown

The prop surface is deliberately familiar: `children`, `components`,
`remarkPlugins`, `rehypePlugins`, `remarkRehypeOptions`, `allowedElements`,
`disallowedElements`, `allowElement`, `skipHtml`, `unwrapDisallowed` and
`urlTransform`.

All 39 prop comparisons against a pinned `react-markdown@10.1.0` produce
identical markup
(<Link href={blob('tests/compatibility.test.tsx')}>`tests/compatibility.test.tsx`</Link>,
which regenerates
<Link href={blob('docs/COMPATIBILITY.md')}>`docs/COMPATIBILITY.md`</Link> on
every run).

| Status | Count | Rows |
| --- | ---: | --- |
| Compatible | 11 | The props listed above |
| Intentionally different | 1 | `className` is ignored at runtime instead of throwing |
| Not supported yet | 1 | `MarkdownAsync` and `MarkdownHooks` do not exist |
| Compatible with a documented change | 1 | A dialect plugin cannot apply to an already compiled document |

We still do not call it a drop-in replacement, because those three rows differ
and you should see them before deciding.

The kit is {kb(sizes['kit-renderer'].gzipBytes - sizes['react-markdown'].gzipBytes)} larger
than `react-markdown` gzipped, and
{' '}{kb(sizes['kit-renderer-gfm'].gzipBytes - sizes['react-markdown-gfm'].gzipBytes)} larger
with GFM on both sides. `markdown-to-jsx` is smaller than both and parses with
its own rules rather than micromark.

Speed is measured by <Link href={blob('benchmarks/run.mjs')}>`benchmarks/run.mjs`</Link>
against the built package, with GFM on both sides, and recorded in
<Link href={blob('benchmarks/README.md')}>`benchmarks/README.md`</Link>. Ratios
are kit divided by `react-markdown@10.1.0`, so below 1.00 is faster.

| Document | Kit median | Baseline median | Ratio |
| --- | ---: | ---: | ---: |
| 1 KB | 2.69 ms | 2.23 ms | 1.21x |
| 10 KB | 16.22 ms | 16.25 ms | 1.00x |
| 100 KB | 206.96 ms | 233.36 ms | 0.89x |

The 1 KB row is a known open item, not a rounding error: fixed per-render cost
dominates a small document, and it is 21% slower there. Parity arrives at
10 KB and the kit is 11% faster at 100 KB. Both numbers come from the same run
on the same machine.
