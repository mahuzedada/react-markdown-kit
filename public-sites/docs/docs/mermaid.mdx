# Mermaid diagrams

```bash
npm install @react-markdown-kit/mermaid
```

```tsx
import Markdown, { defineMarkdownPreset } from '@react-markdown-kit/renderer'
import { mermaid } from '@react-markdown-kit/mermaid'
import '@react-markdown-kit/mermaid/styles.css' // optional: surface, dot grid, border, canvas

const preset = defineMarkdownPreset({ extensions: [mermaid()] })

<Markdown preset={preset}>{content}</Markdown>
```

Try it in the <a href={sites.mermaidDemo}>Mermaid live editor</a>: syntax on
the left, the visual canvas or the preview on the right, plain Mermaid saved.

A diagram is a fenced code block whose language is `mermaid`. The document
stays plain Markdown, and plain Mermaid: GitHub, GitLab, Notion and Obsidian
render the same fence. `mermaid()` is the package's API. Every
```` ```mermaid ```` fence becomes a `diagram` node. The renderer draws
flowcharts and sequence diagrams as static SVG with no Mermaid.js at runtime,
shows every other Mermaid type as source, and lets a host render those with
its own Mermaid.js through the [fallback entry](#host-fallback). The template
plugin keeps the node literal. The editor opens a flowchart and a sequence
diagram on a canvas of its own and every other kind in a source editor with a
live preview.

## Diagram kinds

The plugin reads the first word of the fence, after front matter, `%%{ … }%%`
directives and `%%` comments, the way Mermaid's own `detectType` does. The
word names the **kind**. A kind the plugin registers is rendered; every other
Mermaid keyword is recognised and shown as source.

| Kind | Header | Rendered | Edited |
| --- | --- | --- | --- |
| Flowchart | `flowchart`, `graph`, `flowchart-elk` | Static SVG | Canvas, or text |
| Sequence diagram | `sequenceDiagram` | Static SVG | Canvas, or text |
| Every other Mermaid type (`classDiagram`, `stateDiagram`, `erDiagram`, `gantt`, `pie`, `gitGraph`, `mindmap`, …) | its keyword | Source, or the [host fallback](#host-fallback) | Text |

Each fence carries a **support level**: `static` when a registered kind
parses and renders it, `source` otherwise. A fence that starts with no
Mermaid keyword is kind `unknown`, support `source`. Keywords are
case-sensitive, as in Mermaid; `SequenceDiagram` is `unknown`, and the
diagnostic names the expected spelling.

Kinds are configuration values, like `gfm()`. The default registry is
`[flowchart(), sequenceDiagram()]`, tried in that order. Trim the bundle or
add a kind of your own:

```tsx
import { mermaid, flowchart } from '@react-markdown-kit/mermaid'

const preset = defineMarkdownPreset({ extensions: [mermaid({ kinds: [flowchart()] })] })
```

Two kinds that share a name or a keyword make `mermaid()` throw
`MarkdownConfigurationError` with code `DIAGRAM_KINDS_INVALID`.

## The flowchart subset

| Mermaid | Read as |
| --- | --- |
| `flowchart LR` / `graph TD`, any direction | Left-to-right or top-down auto layout |
| `id[text]`, `id(text)` | Rectangle |
| `id([text])`, `id((text))` | Ellipse |
| `id{text}`, `id{{text}}` | Diamond |
| `id[(text)]` | Cylinder |
| `id[[text]]` | Queue |
| `id>text]` | Note |
| `-->`, `---`, `-.->`, `==>`, `<-->` | Arrow, line, arrow, arrow, bidirectional arrow |
| `-->\|label\|`, `-- label -->` | Edge label |
| `A-->B`, `A --> B` | The same edge, with or without spaces |
| `A & B --> C`, `A --> B --> C`, `;` | Groups, chains, several statements per line |
| `subgraph … end` | Read through; grouping is not drawn |
| `style id fill:…,stroke:…` | Colours |
| `---` front matter with `title:` | Accessible name and caption |
| `%%` comments, `%%{ … }%%` directives, `classDef`, `class`, `click` | Retained lines: kept in the fence, written back unchanged |
| `@{ … }` node config, `e1@` edge ids, `~~~` invisible links | Retained lines, reported as `FLOWCHART_SYNTAX_IGNORED` |
| Anything else | Retained line, reported as `FLOWCHART_UNKNOWN_STATEMENT` |

The flowchart parser reports what Mermaid.js would reject, so an author sees
the mistake before pasting the fence into GitHub or Azure DevOps.

| Code | Severity | When |
| --- | --- | --- |
| `FLOWCHART_UNKNOWN_STATEMENT` | invalid | A statement the parser cannot read, including an `end` outside a subgraph. Retained. |
| `FLOWCHART_LABEL_NEEDS_QUOTES` | invalid | An unquoted label holding `(`, `)`, `[`, `]`, `{`, `}`, `"` or `\|`. The node stays; the writer quotes it. |
| `FLOWCHART_LABEL_EMPTY` | invalid | `A[]`, `A[""]`, `A()` or `\|\|`. The node stays with no text. |
| `FLOWCHART_RESERVED_ID` | invalid | `end`, `subgraph`, `graph`, `flowchart`, `style`, `classDef`, `class`, `click` or `linkStyle` used as a node id. Retained. |
| `FLOWCHART_TRAILING_COMMENT` | invalid | A `%%` comment after a statement on the same line. The statement is read; the comment moves to its own line. |
| `FLOWCHART_LAYOUT_INVALID` | invalid | A rejected `%% rmk-layout` annotation, with the dotted path of the first bad member. |
| `FLOWCHART_SYNTAX_IGNORED` | ignored | `@{ … }` config, `e1@` edge ids, `~~~` links, a `direction` after the first node, a `style` naming a node that never appears. Retained. |

<RenderExample title="Direction down, a decision" markdown={decision} rendererProps={{ extensions: [mermaid()] }} />

The parser is tolerant. A statement it cannot model is a **problem** and a
**retained line**, never a failure of the whole fence: the diagram still
draws, and the line still writes back. The only parse error is a fence whose
first statement is not a flowchart header; that fence renders as source with
`DIAGRAM_INVALID`. A rejected `%% rmk-layout` annotation is problem
`FLOWCHART_LAYOUT_INVALID` with the dotted path of the first bad member; the
diagram is auto-laid out.

## The sequence diagram subset

<RenderExample title="A sign-in with alt/else, activation and a note" markdown={sequence} rendererProps={{ extensions: [mermaid()] }} />

Statements are case-insensitive on the keyword and end at a newline or a
`;`. A line is split at `;` before it is read, as Mermaid does, so write
`#59;` for a semicolon in text.

| Construct | Source | Notes |
| --- | --- | --- |
| Participant | `participant A`, `participant A as Label`, `actor A`, `actor A as Label` | declaration order; an undeclared id is appended on first use |
| Box | `box [colour] [label]` … `end` | the colour stays in the label; a box holds participant statements only |
| Message | `A->B: text` with `->`, `-->`, `->>`, `-->>`, `<<->>`, `<<-->>`, `-x`, `--x`, `-)`, `--)` | `+` or `-` after the arrow activates or deactivates |
| Activation | `activate A`, `deactivate A` | an activation still open at the end is a problem |
| Note | `Note left of A: t`, `Note right of A: t`, `Note over A: t`, `Note over A,B: t` | |
| Frame | `loop t`, `alt t` / `else t`, `opt t`, `par t` / `and t`, `critical t` / `option t`, `break t`, `rect colour` … `end` | nested arbitrarily; a `rect` is drawn as a filled rectangle |
| Autonumber | `autonumber`, `autonumber N`, `autonumber N M` | before the first message; later forms and `autonumber off` are retained and ignored |
| Title | front matter `title:`, `title X`, `title: X` | caption and accessible name |
| Text | `<br/>`, `#NN;`, `#quot;`, `#lt;`, `#gt;` | decoded |

Layout is deterministic and needs no annotation: participants are columns in
declaration order, each message, note and frame edge takes one row, a self
message draws a loop, activations are bars on the lifeline, frames span the
participants they touch. The kind has a writer, so the editor opens it on
the [sequence canvas](#the-sequence-canvas) and every gesture is written back
as plain Mermaid; [what the sequence writer emits](#what-the-sequence-canvas-writes)
is listed below.

The parser reports what it cannot model. `invalid` problems are statements
Mermaid.js itself rejects; `ignored` problems are statements Mermaid.js
accepts that the plugin does not draw. Every ignored statement is a retained
line.

| Code | Severity | When |
| --- | --- | --- |
| `SEQUENCE_DIAGRAM_UNKNOWN_STATEMENT` | invalid | A statement that is not sequence diagram syntax. After a `;` the message names the entity codes to use instead of `;`, `&`, `<` and `>`. |
| `SEQUENCE_DIAGRAM_DEACTIVATE_INACTIVE` | invalid | `deactivate` or a `-` arrow on a participant that is not active. |
| `SEQUENCE_DIAGRAM_END_WITHOUT_OPENER` | invalid | An `end` with no open frame or box. |
| `SEQUENCE_DIAGRAM_SECTION_OUTSIDE_FRAME` | invalid | `else`, `and` or `option` outside `alt`, `par` or `critical`. |
| `SEQUENCE_DIAGRAM_FRAME_UNCLOSED` | invalid | A frame or box still open at the end. |
| `SEQUENCE_DIAGRAM_RESERVED_ID` | invalid | A message end or note target named like a sequence keyword (`end`, `loop`, `note`, …), which Mermaid.js reads as the keyword. |
| `SEQUENCE_DIAGRAM_ACTIVATION_UNCLOSED` | ignored | An activation still open at the end. Mermaid.js accepts it; the bar is drawn to the last item. |
| `SEQUENCE_DIAGRAM_STATEMENT_IGNORED` | ignored | `link`, `links`, `properties`, `details`, `create`, `destroy`, `accTitle`, `accDescr`, half arrows, `()` connections, `@{ … }` participant config, `autonumber off`, a later `autonumber`. |

Problems name a line, a keyword or an id, never a line of your content. They
reach the compiled document as diagnostics, listed under
[Diagnostics](#diagnostics), and the source editor lists them under the
textarea with `invalid` first.

## What the editor writes

Mermaid has no syntax for where a box sits, how big it is, how an edge
bends, or free text on the canvas. So when a flowchart
is edited, the canvas writes the graph as ordinary Mermaid and the geometry
as one layout annotation, a `%% rmk-layout v1 {…}` comment on the last
line. Every other renderer ignores the comment; this plugin reads it back,
so a drawing round-trips without loss. A hand-written flowchart with no
annotation is auto-laid out, and an untouched fence is written back byte
for byte.

The writer emits, in order: one `---` block holding `title:` and the retained
front-matter lines, the header, node lines, edge lines, `style` lines, the
retained body lines in their original order, and the annotation last. Ids the
parser accepted are written unchanged, `my-box` included; only an id that is
not a valid Mermaid id is rewritten. What the property bar sets is written
as Mermaid: a rounded rectangle as `(text)` and a square one as `[text]`,
a node's stroke width, dashes and text colour as `stroke-width`,
`stroke-dasharray` and `color` on its `style` line, and an edge's style in
its link token (`-.->` dotted, `==>` thick, `--o` and `--x` heads, `o--o`
both ways). A canvas edit can lose what the canvas cannot draw: `subgraph`,
invisible (`~~~`) and extra-long links, a link whose two heads differ, some
bracket shapes, `linkStyle` and `style` properties other than those.
The parse names these under `lossy`, and the editor shows them before the
first edit.

<RenderExample title="With a layout annotation: elbow routing and exact positions" markdown={withLayout} rendererProps={{ extensions: [mermaid()] }} />

The annotation is a versioned format with a formal specification,
`LAYOUT_ANNOTATION.md`, shipped with the package, and a JSON Schema,
`LAYOUT_ANNOTATION_JSON_SCHEMA`, exported from the root. The payload is one
JSON object: `nodes` keyed by Mermaid id with position, size, stroke width
and text slots; `edges` keyed by endpoints (`a->b`, `a->b#2` for a second
edge between the same nodes) with routing, waypoints and attach points;
`texts` and `loose` for shapes Mermaid cannot express. The syntax stays
authoritative for the graph and colours; the annotation never repeats them.

Reading is fail-closed: an annotation with a wrong type, an unknown version
or a second annotation in the same fence is rejected as a whole, the diagram
is auto-laid out, and the compile result carries a `DIAGRAM_LAYOUT_INVALID`
warning with the dotted path of the first problem (`nodes.web.x`). Members
the reader does not know are ignored, so a later minor revision can add
fields without breaking older readers. The writer emits a canonical form
(fixed member order, compact JSON, numbers to two decimals), so a diff
shows only what moved. `readLayoutAnnotation` and `writeLayoutAnnotation`
are the reference reader and writer.

## What the sequence canvas writes

A sequence diagram needs no annotation: its layout is deterministic, so the
writer emits plain Mermaid and nothing else. In order: one `---` block
holding `title:` and the retained front-matter lines (omitted when both are
empty), the header `sequenceDiagram`, `autonumber` when numbering is set,
the participants in declaration order as `participant id` or `actor id`
with ` as Label` when the label differs from the id (each `box … end` opens
where its first participant sits), the retained body lines, then the items
depth first at four spaces per level: a message as `A->>+B: text`, a note as
`Note over A,B: text`, a frame as `alt label` … `else label` … `end`.

Activation bars come from the model's `activations`. A bar whose messages
carry `+` and `-` is written with those suffixes; any other bar is written
as `activate A` and `deactivate A` statements after the items where it
starts and ends. Text goes through the same escape as the flowchart writer
plus `#59;` for `;`, since sequence text is unquoted: `#35;` for `#`,
`#38;`, `#37;`, `#quot;`, `#lt;`, `#gt;` and `<br/>` for a line break.

Retained lines are re-emitted verbatim: `link`, `links`, `properties`,
`details`, `accTitle`, `accDescr`, `%%{ … }%%` directives and `%%`
comments. `create` and `destroy` cannot keep their position among the
messages, so the parser names `create-destroy` under `lossy` and the writer
drops them; the canvas mounts read-only behind a notice until "Edit on
canvas" is chosen. An untouched fence is written back byte for byte. The
written output is a fixed point, parses back to the same model, and is
accepted by Mermaid.js for every documentation example in the corpus
([`conformance.dom.test.ts`](https://github.com/mahuzedada/react-markdown-kit/blob/main/plugins/mermaid/tests/conformance.dom.test.ts)).

## What the renderer emits

```html
<figure data-rmk-diagram="mermaid" data-rmk-diagram-kind="sequenceDiagram" data-rmk-diagram-support="static">
  <svg viewBox="0 0 640 260" role="img" aria-label="Diagram">…</svg>
  <figcaption>title</figcaption>
</figure>
```

`data-rmk-diagram` carries the fence format (`mermaid`, or the legacy
`diagram` and `drawing`), `data-rmk-diagram-kind` the detected kind and
`data-rmk-diagram-support` the support level. A fence shown as source keeps
its body inside the figure:

```html
<figure data-rmk-diagram="mermaid" data-rmk-diagram-kind="classDiagram" data-rmk-diagram-support="source">
  <pre><code class="language-mermaid">…</code></pre>
</figure>
```

- **No script, no `foreignObject`, no external references.** Shapes are
  `rect`, `ellipse`, `path` and `text`. Colours land as attributes; a value
  that is not a colour is dropped by the parser.
- **Server-renderable.** The SVG is hast, built with no DOM and no React, so
  it works in a server component and in static rendering.
- **Styled by the optional stylesheet only.** `data-rmk-diagram` is the hook;
  the `classNames` prop's `diagram` part adds your own class to the figure.
- **Unreadable input stays visible.** A fence a registered kind cannot read
  renders as source inside the figure with `data-rmk-diagram-error` set and a
  `DIAGRAM_INVALID` diagnostic on the compiled document.

## Host fallback

The plugin never depends on Mermaid.js. A host that wants class diagrams,
Gantt charts or any other type drawn can render them itself, in the browser,
with `@react-markdown-kit/mermaid/client`:

```tsx
import Markdown, { defineMarkdownPreset } from '@react-markdown-kit/renderer'
import { mermaid } from '@react-markdown-kit/mermaid'
import { diagramFallback } from '@react-markdown-kit/mermaid/client'

// Host code: how the SVG is made is the host's choice. Mermaid.js here, but
// Kroki or a server endpoint fit the same signature.
async function render(source: string, kind: string): Promise<string> {
  const { default: mermaidJs } = await import('mermaid')
  const { svg } = await mermaidJs.render(`rmk-${kind}-${Date.now()}`, source)
  return svg
}

const preset = defineMarkdownPreset({ extensions: [mermaid(), diagramFallback({ render })] })
```

`diagramFallback({ render })` is an extension named `mermaid-fallback` that
registers one renderer component, the `figure`. It passes every figure
through unchanged unless the figure carries `data-rmk-diagram-support="source"`
or `data-rmk-diagram-error`. For those, the first client render is the
server markup, so hydration agrees. After mount it calls `render` with the
fence body and the kind, and a resolved string replaces the `pre` with
`<div data-rmk-diagram-fallback>` holding the markup. The host chose the
renderer and owns that output; the kit's policy does not run on it. A
rejected or empty result keeps the source. The entry loads React and is
built with the `'use client'` banner, so it goes in a client component; the
root entry stays headless.

## Theme tokens

The flowchart takes its colours from the fence. The sequence diagram has no
colours in its syntax, so its renderer reads custom properties, each with a
fallback from Mermaid's default theme. An unstyled document looks like

`fill="var(--rmk-diagram-note-fill, #fff5ad)"`. `styles.css` declares no

## Diagnostics

`compileMarkdown` reports diagram problems on the document, with the range
narrowed to the fence line the problem names. A host that lints documents
before saving reads the codes:

| Code | Severity | When |
| --- | --- | --- |
| `DIAGRAM_INVALID` | warning | A registered kind could not read the fence. It is shown as source. |
| `DIAGRAM_KIND_UNKNOWN` | warning | The fence does not start with a Mermaid keyword. A case slip names the expected spelling. |
| `DIAGRAM_KIND_UNSUPPORTED` | info | A Mermaid keyword no registered kind renders. The fence is shown as source. |
| `DIAGRAM_LAYOUT_INVALID` | warning | The `%% rmk-layout` annotation was rejected; `path` holds the first bad member. |
| `DIAGRAM_SYNTAX_INVALID` | warning | One per `invalid` problem, at most 20 per fence: "Line N: …". Mermaid.js would reject the fence. |
| `DIAGRAM_SYNTAX_IGNORED` | info | One per `ignored` problem, at most 20 per fence: "Line N: …". Mermaid.js accepts it; the plugin does not draw it. |

The `error` string of a parse error is on the node, not in a message, so a
message never quotes your content.

## Templates

A placeholder inside a diagram is never resolved. The node is literal,
exactly like a code block, so runtime data cannot reach a box's text, colour
or geometry.

## Editor

`@react-markdown-kit/mermaid/editor` adds the editing half: the same
extension under the same name, one more capability, so it replaces the
renderer's `mermaid()` in a preset.

```tsx
import { MarkdownEditor } from '@react-markdown-kit/editor'
import { mermaid } from '@react-markdown-kit/mermaid/editor'

const preset = defineMarkdownPreset({ extensions: [gfm(), mermaid()] })

<MarkdownEditor preset={preset} value={value} onChange={setValue} />
```

A block shows its kind and support level in a header row. A flowchart and
a sequence diagram open on a canvas, with a Text toggle to the source editor.
Every other kind opens in the source editor: a textarea, a live preview above
it rendered by
the kind, and the problems under it with line numbers, `invalid` first with
the prefix "Mermaid rejects:". Source mode never blocks a keystroke and
never rewrites the text. Undo goes through the editor's history.

### The flowchart canvas

Boxes, connectors and text are drawn by picking a tool and
dragging; connectors bind to the boxes they touch and follow them. The
property bar works like Excalidraw's: a colour swatch sets the fill, stroke
and text colour in one click, and two custom pickers set any background or
text colour; stroke width (thin, medium, bold) and style (solid, dashed,
dotted) apply to boxes and connectors; a rectangle has sharp or round
corners; a connector takes an arrow, circle or cross head or none, elbow
routing and one or two directions. Cmd/Ctrl+D or **Duplicate** copies the
selection. New rectangles are square, Mermaid's `[text]`. **Copy as Mermaid** copies the same text the fence
saves, layout annotation included, so pasting it into another canvas keeps
the positions and every other renderer ignores the comment. A flowchart with
`lossy` features mounts read-only behind a notice that names them, with
"Edit on canvas" and "Edit as text" as the two ways on.

Several shapes are selected with Shift+click, by dragging a box around them
on the background, or with Cmd/Ctrl+A. The selection works the way it does
in Excalidraw: every member gets a thin outline and the selection a dashed
frame with handles. A corner handle scales the whole selection evenly from
the opposite corner, a side handle stretches it along one axis, and Alt
scales from the centre; positions, sizes and waypoints scale, text and
stroke widths keep their size, and bound connectors follow their boxes.
Dragging any member, or the empty space inside the frame, moves the
selection; clicking one member without dragging narrows the selection to
it; the arrow keys nudge it by 1px, 10px with Shift, as one undo step. The
colour and connector settings apply to every selected shape, and a click
that moves nothing writes nothing.

### The sequence canvas

A sequence diagram is edited on its rendered picture. Every gesture is one
operation on the model, written back with the sequence writer and committed
as one history entry; inline typing merges into one entry under the same
300 ms rule as the source editor. A gesture that would make Mermaid.js
reject the fence is not offered. The lossy lock and the "Edit on canvas"
notice work as for a flowchart.

| Gesture | Result |
| --- | --- |
| Click, Escape | Select one participant, message, note or frame; clear the selection |
| Delete, Backspace | Remove the selection. A participant takes its messages and notes; a frame unwraps its items |
| Enter, double click | Edit the label inline. Enter or blur closes the field; Escape restores the text |
| **Add participant**, **Add actor** | Append one with a fresh id and label, selected |
| Drag a participant box sideways | Reorder the columns; a box moves as one unit |
| Drag from a lifeline to a lifeline | Add a `->>` message at that row, a self message on the same lifeline; its text opens for editing |
| Drag a message or note up or down | Reorder it among its siblings |
| Property bar, participant | Participant or actor |
| Property bar, message | Solid or dotted line; arrow, open, cross or no head; two-way; activation `+`, `-` or none; swap ends |
| Hover a gap on a lifeline, click **+** | Add a note over that participant at that row |
| Property bar, note | `left of`, `right of` or `over`, with a second participant for `over` |
| **Wrap in**, with a message or note selected | Wrap it, or a Shift+click range of siblings, in `loop`, `alt`, `opt`, `par`, `critical`, `break` or `rect`; the label opens for editing |
| Property bar, frame | Add a section (`else`, `and`, `option`) or unwrap the frame |
| Drag a frame's bottom edge | Extend or shrink it over the following siblings |
| **Autonumber** | Set or clear `autonumber` |
| **Copy as Mermaid** | Copy the text a commit would save |

A participant's id is kept on rename unless the label was the id, in which
case the id follows a sanitised form of the new label, so hand-written
diagrams keep their ids. Read-only editors show the picture only. Every
control's label comes from the `diagram.` label map.

### Bringing your own canvas

`mermaid({ editors })` maps a kind name to the component that edits it. The
built-in map is `{ flowchart, sequenceDiagram }`; a name in your map
replaces the built-in component, and a kind of your own gets a canvas the
same way. The block owns the mode, the lossy lock, undo history and the
commit; the component draws the parse and hands source back.

```ts
interface DiagramKindEditorProps {
  readonly nodeKey: NodeKey
  readonly kind: DiagramKind
  readonly source: string
  readonly parse: DiagramParse<unknown>
  /** True while the block locks the canvas behind the lossy notice (a lossy source not yet acknowledged). A read-only editor never mounts the component: the block renders the kind's output instead. */
  readonly readOnly: boolean
  /** Writes `source` to the node as one history entry. `merge` folds it into the previous commit under the 300 ms rule. */
  readonly commit: (source: string, options?: { readonly merge?: boolean }) => void
}
type DiagramKindEditor = ComponentType<DiagramKindEditorProps>
```

```tsx
import { mermaid, type DiagramKindEditorProps } from '@react-markdown-kit/mermaid/editor'

function TimelineCanvas({ kind, parse, readOnly, commit }: DiagramKindEditorProps) {
  const model = parse.model as TimelineModel
  const save = (next: TimelineModel) => commit(kind.write!(next, { retained: parse.retained }))
  // The root carries data-rmk-diagram-focus so the block can focus it after an insert.
  return <div className="rmk-diagram-canvas" tabIndex={0} data-rmk-diagram-focus>…</div>
}

const preset = defineMarkdownPreset({
  extensions: [gfm(), mermaid({ kinds: [flowchart(), sequenceDiagram(), timeline()], editors: { timeline: TimelineCanvas } })],
})
```

A kind edits on its component only while it also has `write`; without a
writer the block stays in the source editor.

The toolbar gains one insert button per registered kind: id `diagram` for the
flowchart and `diagram-<kind>` for the others (`diagram-sequenceDiagram`),
group `diagram`, icon from the kind. Override a label through the editor's
`labels` prop by that id; the `diagram.` prefix stays reserved for the
canvas labels (`DIAGRAM_LABELS`).

### A detached tool row

Each canvas draws its tool row (the shape tools, the property bar, Copy as
Mermaid, the width presets; the participant tools and autonumber on the
sequence canvas) along its own top edge. A host that builds its own chrome
around the editor, the way [headless editing](/docs/editor/headless) lets it
build its own formatting toolbar, can take that row out of the block:
mount `<DiagramToolbar>` from the editor entry wherever the tools should
sit, inside `<MarkdownEditorProvider>` or with
`editor={useMarkdownEditor(...)}`, and every canvas of that editor renders
its tools into it instead.

```tsx
import { MarkdownEditorContent, MarkdownEditorProvider, useMarkdownEditor } from '@react-markdown-kit/editor'
import { DiagramToolbar, mermaid } from '@react-markdown-kit/mermaid/editor'

function Composer({ value, onChange }) {
  const editor = useMarkdownEditor({ value, onChange, extensions: [mermaid()] })
  return (
    <MarkdownEditorProvider editor={editor}>
      <header className="app-bar">
        <DiagramToolbar placeholder="Open a flowchart or a sequence diagram to draw" />
      </header>
      <div className="rmk-editor">
        <MarkdownEditorContent aria-label="Document" />
      </div>
    </MarkdownEditorProvider>
  )
}
```

The slot shows one canvas's tools at a time: the canvas that last had
focus, or the first on the page before any has; when that block is
deleted or switched to text, the oldest remaining canvas takes over, and
the other canvases show no row of their own. Focus in the detached row
keeps its canvas active, so the property bar and the keyboard shortcuts
behave as they do inline. `placeholder` renders while no canvas is on
screen (the document has none, or every diagram is a kind edited as
text). The slot's root carries `rmk-editor`, so the `--rmk-diagram-*`
tokens you map on that class reach it wherever it sits, plus
`rmk-diagram-toolbar-host` and `data-rmk-diagram-toolbar="filled"` or
`"empty"` to style it by; the row inside keeps its inline look
(`.rmk-diagram-toolbar.is-detached`) until you restyle it. Without a
mounted `<DiagramToolbar>` nothing changes. The
<a href={sites.mermaidDemo}>live editor</a> puts its row in the pill floating
over the top-left corner of the canvas this way.

The <a href={sites.mermaidDemo}>live editor</a> shares a diagram by link: the
source, annotation included, is deflated into the URL hash as
`#pako:<base64url>` (the same zlib form mermaid.live uses, with a `#base64:`
fallback), so nothing is uploaded. Its **Share** panel gives the link, an
"Open in visual editor" badge for a README, and an `?embed=1` iframe snippet
that hides the site chrome. The format is tested in
[`tests/mermaid-share.test.ts`](https://github.com/mahuzedada/react-markdown-kit/blob/main/tests/mermaid-share.test.ts).

Only the `/editor`, `/canvas` and `/client` entries load React. A Node service that
renders or templates diagrams imports the root entry and installs neither
React nor Lexical.

## Standalone canvas

`@react-markdown-kit/mermaid/canvas` is the same canvas without a Markdown
editor: Mermaid in, Mermaid out. It fills whatever container you give it
and floats its tools over the drawing, down the left edge or along the top,
the way Excalidraw lays out its canvas.

```tsx
import { MermaidCanvas } from '@react-markdown-kit/mermaid/canvas'
import '@react-markdown-kit/mermaid/styles.css'

<div style={{ height: 600 }}>
  <MermaidCanvas value={source} onChange={setSource} />
</div>
```

```ts
import { createMermaidCanvas } from '@react-markdown-kit/mermaid/canvas'

const canvas = createMermaidCanvas(document.getElementById('diagram')!, {
  value: 'flowchart LR\n  a[Web] --> b[API]',
  onChange: (source) => save(source),
})
canvas.update({ zoom: 1.5 })
canvas.destroy()
```

Props: `value` / `defaultValue` / `onChange` (the Mermaid source, a
flowchart's with its layout line), `toolbar` (`left`, the default, `top` or
`none`), `zoom`, `drawingStyle` (`clean` or `ink`), `align` (`center`, the
default, or `start`), `readOnly`, `labels` (UI strings by key), `kinds`,
`editors`, `fallbackTitle`, `onFocusChange`, `className`, `style`, and
`children`, which render over the surface for chrome of your own. The
component keeps its own undo history (Cmd/Ctrl+Z, Shift+Cmd/Ctrl+Z,
Ctrl+Y); a `value` changed from outside is one more entry in it. A kind
without a canvas shows its static render or its source, and a flowchart
with lossy features is locked behind the same notice the block shows.
`createMermaidCanvas` returns `{ getValue, setValue, update, destroy }`.
The entry loads React and ReactDOM, never Lexical or the editor package.
`--rmk-mermaid-canvas-background` sets the page colour behind the grid and
`--rmk-mermaid-tools-top` moves the tool island under chrome of your own.

## Programmatic API

The plugin is the API. The root entry exports `mermaid(options?)` with
`fallbackTitle` (names an untitled diagram) and `kinds` (the registry), the
kind factories `flowchart()` and `sequenceDiagram()`, `MERMAID_KEYWORDS`
(every Mermaid type the detector recognises) and the types a kind of your
own implements: `DiagramKind`, `DiagramParse`, `DiagramParseError`,
`DiagramProblem`, `DiagramRenderOptions`, `DiagramWriteOptions`,
`RetainedLine`. No parser, renderer or writer is exported on its own.

A kind is a plain object: a `name` and `keywords` for detection, a `label`,
a `starter` for the insert button, `parse(source)` returning a model with
`problems`, `retained` lines and `lossy` features, an optional
`render(model, options)` returning hast (absent means support `source`), and
an optional `write(model, options)` that re-emits the retained lines.

On `/editor`, `mermaid()` also takes `style` (`clean` or hand-drawn `ink`),
`newBlockWidth`, `sourceEditor` (`false` hides the textarea, so a block
edited as text shows the preview and the problems only), `align` (`start`,
the default, keeps a drawing at the top-left of its canvas, as a block sits
in a document; `center` puts it in the middle of the room the canvas has,
on both axes, and scales one taller than that room down to fit, the way a
page-as-canvas editor shows a diagram, without moving its coordinates) and
`editors` (the canvas component per kind name). The editor entry exports the types
`DiagramKindEditor`, `DiagramKindEditorProps` and `DiagramKindEditors` for
a canvas of your own, and `<DiagramToolbar>` (`DiagramToolbarProps`:
`editor`, `className`, `placeholder`), the slot that takes the canvases'
tool rows out of the blocks. The JSON Schemas for the layout annotation and the
legacy payloads are exported for validating generated text.
